Semantic HTML Cheat Sheet

A quick reference for every tag covered in the seminar.

Page Structure

<header> — The top of the page. Contains introductory content like the site title or logo. Tells the browser and anyone reading the code where the page begins.

<nav> — A group of navigation links. Screen readers can jump directly to this element, skipping everything above it.

<main> — The primary content of the page. Should only appear once per page. Contains content that is unique to this page and not repeated across the site.

<footer> — The bottom of the page. Contains closing information such as credits, copyright notices, or contact links.

Content Tags

<article> — Self-contained content that makes sense on its own. Examples: a blog post, a news story, a product listing.

<section> — A thematic group of content within a page. Use when your main content has multiple distinct parts that belong together.

<h1> to <h6> — Headings that form a document outline. There should only be one <h1> per page. Subheadings use <h2>, sections within those use <h3>, and so on. Think of it as a table of contents, not just a font size setting.

<p> — A paragraph of text.

<a> — A link. Always use this for navigation items and anything clickable that takes the user somewhere. Unlike a <div>, it is keyboard focusable by default.

What to Avoid

<div> — A generic container with no meaning attached to it. The browser, search engines, and screen readers learn nothing from it. Use it only as a last resort when no semantic tag fits.

Quick Rules to Remember

Only one <h1> per page.

Only one <main> per page.

If it is a link, use <a>. If it is a button, use <button>.

If it is a heading, use <h1> through <h6> — not a styled <div>.

When in doubt, ask: does this tag describe what is inside it? If not, find one that does.
